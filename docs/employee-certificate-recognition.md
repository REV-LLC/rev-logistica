# Employee EPS/ARL certificate recognition

An Office/Admin upload in personnel Documents, tagged EPS or ARL, creates an EmployeeAffiliationRecognition job atomically with the EmployeeDocument and FileObject. Other categories and operational evidence never enqueue recognition. A production worker processes one document at a time; jobs persist in PostgreSQL, use SKIP LOCKED claims with four-minute leases, and recover interrupted work up to two attempts. An idempotent periodic reconciliation covers uploads made by the previous API during rolling deployment.

The server reads PDF text with Poppler and scans images/scanned PDFs with local Spanish Tesseract. No document is sent to an AI/OCR provider. Files remain unchanged in R2; private temporary files are removed. Processing is bounded to 10 MB, four PDF pages and native-command timeouts; larger/unsupported files remain saved for office review. Raw extracted text, credentials and document IDs are not logged or persisted in recognition results.

Automatic assignment requires a single matching catalog entity of the tagged kind, a full employee name and exact identity number, certificate/affiliation wording, active status and an unambiguous issue date within 90 days. Expired, future, multi-employee, ambiguous, unreadable or inactive-entity certificates require review. The uploader must still be active Office/Admin and the employee/document must still exist and match. A different existing affiliation or a concurrent change is not overwritten. Assignment locks the provider, employee and recognition row; only the selected EPS or ARL ID/name mirror is updated, preserving the other affiliation.

Office reviews results at /employees/affiliations?tab=certificates. A manual assignment requires viewing/checking the employee and entity, explicit confirmation, an active provider of the correct kind and an unchanged current affiliation. Office may close a review without changing the employee. Each result records its source file, policy version, method, candidate, previous provider, identity/date checks and automatic/manual application metadata. Deleting an uploaded document detaches the recognition without erasing its audit result.

MiREV continues to show the existing readonly EPS/ARL fields from the shared employee record, without an OCR/review interface. Its API needs no redeploy because the employee/profile and document contracts do not change.

Validation before publication: full API unit suite, real local PostgreSQL queue/ownership/race/review tests, real Spanish image and scanned-PDF OCR, and Chrome office review/preview/assignment checks on fictional data. Production receives no fixture employees or files. Production-only manual image publication keeps staging excluded; native readers and Spanish model are checked inside the immutable image before promotion.
